# Adrobot · Keitaro

Локальный интерфейс для создания кампаний Keitaro и управления офферами в существующих потоках. Бэкенд использует FastAPI, SQLAlchemy 2 и PostgreSQL. Интерфейс работает в браузере после запуска через Docker Compose.

## Запуск

Понадобятся Docker с Compose v2 и действующий Admin API Key из тестового Keitaro. В панели Keitaro ключ доступен в **Профиль → API-ключи**. Учётной записи нужен доступ к кампаниям, потокам, офферам, справочникам и отчётам.

```bash
cp .env.example .env
```

Укажите `KEITARO_API_KEY` в локальном `.env`. `KEITARO_URL` — HTTPS-адрес трекера, например `https://tlgk.host`. `CAMPAIGN_PREFIX` задаёт префикс создаваемых кампаний, по умолчанию `test_kryvanos_`. `KEITARO_TIMEZONE` задаёт часовой пояс отчёта «Клики сегодня». `APP_PORT` меняет локальный порт.

```bash
docker compose up --build -d --wait
```

Приложение доступно на [127.0.0.1:8000](http://127.0.0.1:8000), описание HTTP API — на [/docs](http://127.0.0.1:8000/docs). Compose публикует приложение на loopback. API-ключ читает только сервер.

```bash
docker compose ps --all
docker compose logs migrate
docker compose down
```

После остановки данные остаются в томе `pgdata`.

## Миграции

При запуске сервис `migrate` ждёт готовности PostgreSQL и выполняет `alembic upgrade head`. FastAPI стартует после успешного завершения миграции.

```bash
docker compose up -d --wait db
docker compose run --rm migrate uv run alembic current
docker compose run --rm migrate uv run alembic upgrade head
```

Для проверки отката в одноразовой базе выполните `alembic downgrade base` и повторный `alembic upgrade head`. Откат до `base` удаляет локальные черновики, архив офферов, закрепления долей и историю создания кампаний. Кампании в Keitaro сохраняются.

## Работа с кампаниями

1. На странице **Создать кампанию** введите название, двухбуквенный код страны и ID активного оффера. Домен, группа и источник загружаются из Keitaro. В тестовом трекере группа и источник **FORTESTS** выбираются по умолчанию.
2. После создания откроется редактор. Первый поток направляет выбранное гео на Google. Второй принимает остальной трафик и направляет его на выбранный оффер.
3. Откройте кампанию из списка или найдите её по ID. В редакторе **Обновить из Keitaro** загружает потоки, опубликованные офферы и клики за текущий день. Потоки без офферов тоже отображаются. Кнопка **Открыть в Keitaro** ведёт в админку кампании.
4. Добавьте оффер через поиск по ID или названию. **Удалить** даёт офферу 0% в черновике. **Вернуть** восстанавливает оффер из архива и пересчитывает доли. **Закрепить** сохраняет текущую долю при пересчёте.
5. **Опубликовать** отправляет состав офферов в Keitaro. **Отменить** возвращает сохранённую версию потока. При обновлении из Keitaro офферы, удалённые в трекере, попадают в архив после синхронизации опубликованного потока.

При изменении списка активных офферов остаток до 100% делится поровну между незакреплёнными. Целые проценты распределяются по порядку офферов. Исходные доли из Keitaro отображаются как есть, включая суммы меньше 100%. Прочерк вместо кликов означает, что отчёт недоступен.

PostgreSQL хранит черновики, архив, локальные закрепления и идентификаторы операций создания. При сбое во время создания повторите отправку с теми же полями в той же вкладке. Кампания активируется после создания обоих потоков. При конфликте с изменениями в Keitaro отмените черновик, обновите поток и внесите изменения повторно. Compose запускает один процесс API, который сериализует операции одной кампании.

## Проверки

Проверки используют отдельный проект Compose и одноразовую PostgreSQL. Тестовый HTTP-адаптер воспроизводит ответы Keitaro без рабочего ключа.

```bash
docker compose -f compose.test.yaml up --build --abort-on-container-exit --exit-code-from checks
docker compose -f compose.test.yaml down --volumes
```

Проверка создания кампании, добавления оффера и публикации в Chromium.

```bash
docker compose -f compose.test.yaml run --rm --build browser
docker compose -f compose.test.yaml down --volumes
```
